# 💡 Idea Platform

Внутрикорпоративная платформа управления идеями сотрудников.
Централизованное место, где любой сотрудник может подать идею, проблему
или предложение по автоматизации — и отследить её путь от подачи до внедрения.

---

## 🎯 Боли, которые решает

- **Идеи тонут в мессенджерах** — нет единого места, Slack/Teams-сообщения
  теряются и никто не несёт ответственности за рассмотрение
- **Чёрный ящик** — сотрудник подал идею и не знает, что с ней происходит;
  платформа решает это через полную историю статусов
- **Нет SLA на рассмотрение** — встроен дедлайн 5 дней с автоматическим
  уведомлением по истечению
- **Нет мотивации участвовать** — без признания люди перестают подавать идеи;
  решается через систему достижений и героев
- **Дубликаты** — одну и ту же идею подают десятки раз; встроен механизм
  маркировки дубликатов со ссылкой на оригинал
- **Менеджер не видит картину** — кто генерирует идеи, какие команды активны,
  где воронка «протекает»

## 🔄 Жизненный цикл идеи

```text
DRAFT → SUBMITTED → ON_REVIEW → APPROVED → VOTING → IN_PROGRESS → PILOT → IMPLEMENTED
↘ REJECTED / POSTPONED / DUPLICATE
```

## ⚙️ Функционал

### 👤 Для сотрудника (USER)
- Подача идей трёх типов: 💡 Идея, 🐛 Проблема, ⚙️ Автоматизация
- Описание, ожидаемый эффект, приоритет, вложения (до 10 MB)
- **Анонимный режим** подачи
- Взвешенное голосование: `MUST_HAVE`, `USEFUL`, `NEEDS_IMPROVEMENT`, `NOT_GREAT`
- Комментирование идей
- Личный кабинет с историей идей и достижениями

### 🔍 Для ревьюера (REVIEWER)
- Очередь ревью с сортировкой по дате и SLA-дедлайном
- Решения: Одобрить / Отклонить / Отложить / Дубликат
- Продвижение по воронке: `IN_PROGRESS → PILOT → IMPLEMENTED`
- Ссылка на Jira-задачу при переводе в работу

### 📊 Для менеджера (MANAGER)
- Dashboard с воронкой идей и конверсиями
- Классификация участников: **Innovator / Early Adopter / Participant / Observer / Inactive**
- Активность команд: `engagementRate = activeUsers / membersCount × 100%`
- Топ инноваторов и топ команд

### 🛡️ Для администратора (ADMIN)
- Управление структурой: Division → Tribe → Team
- Управление пользователями и ролями
- Настройка плагинов (auth-провайдеры и др.)

| 🐝 Пчела     | Автоматизации            | 1/5/15/30/50    |

| 🐬 Дельфин   | Голоса + комментарии     | до 200 голосов  |

**Уровни:** `NOVICE → EXPLORER → MASTER → EXPERT → LEGEND`

## 🏗️ Архитектура

- **Backend:** Java 21, Spring Boot 3.5, Spring Security, Spring Data JPA
- **Frontend:** Thymeleaf + Bootstrap 5
- **БД:** PostgreSQL 15 + Flyway migrations
- **Auth:** нативный логин/пароль или Keycloak OAuth2 (plug-in)
- **Plugin API:** модульная архитектура — auth-провайдеры подключаются
  как отдельные модули без изменения ядра

### Структура модулей

```idea-platform/
├── idea-platform-core # Основное приложение
├── idea-platform-plugin-api # Интерфейсы для плагинов
└── idea-platform-keycloak # Keycloak auth-плагин
```


### Org-структура

```text
Division → Tribe → Team → User
```
